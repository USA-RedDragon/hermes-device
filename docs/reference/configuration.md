# Configuration

The program reads `~/.config/talaria/config.yaml` (on macOS, the same path under your home directory), or the file you give with `-c`. Then it reads environment variables, then flags, and a later source wins. A `config.yaml` in the current directory is not read. `talaria setup` writes the file when it does not exist, and never changes an existing one unless you pass `--overwrite-config`.

Restart the service after you change the file: `systemctl --user restart talaria` on Linux. On macOS, run `talaria setup` again.

## From the sample config

The sample file `config.example.yaml` in the repository holds every key with its description. Two sections of it:

<!-- docgen:code file=config.example.yaml symbol=hub -->
```yaml
hub:
  # Base URL of hermes-hub, for example https://hub.example.com. Needed by login, run, chat and acp
  # url: ""
  # Device token for run, instead of the one login stored, for a service device such as the sandbox pod. Wins over hub.token-file and the token store
  # token: "(secret)"
  # File holding only the device token for run, for example a mounted Kubernetes secret. Must not be readable by others. Wins over the token store
  # token-file: ""
```
<!-- /docgen:code -->

<!-- docgen:code file=config.example.yaml symbol=device -->
```yaml
device:
  # Absolute directories commands may run in. A command whose working directory is outside all of them is refused. Defaults to the home directory
  # roots: []
  # Directory Hermes uses on this device for its shell snapshot files. Defaults to the system temp directory
  # tmp-dir: ""
  # Shell used to run commands
  shell: "bash"
  # Most output bytes per command that run keeps for a resume of the exec leg until the plugin confirms them. Older output of a command is dropped, and the plugin shows the gap
  resume-buffer: 1048576
  # Longest time run keeps commands running after the exec leg drops, waiting for a resume. The plugin's grace_seconds applies when it is shorter
  max-grace: "10m"
  # Memory cap of each agent command, as bytes or with a K, M, G or T suffix (powers of 1024), for example 4G. On Linux with a systemd user manager, run starts each command in a systemd scope of its own with this MemoryMax, so the kernel kills only a command that uses more, and the agent is told so. auto is 75% of the MemoryMax of the cgroup that run runs in (the talaria service), or 4G when that has no limit. 0 or off runs commands in run's own cgroup, without a cap of their own. No effect on macOS
  command-memory-max: "auto"
```

## MCP servers on this computer

The agent can use tool servers (MCP) that run on this computer, for tools that must work on your own files. Only servers you list can run, and the server cannot add one. A server starts when the agent first uses it and stops after `mcp.idle-timeout`.

```yaml
mcp:
  servers:
    files:
      command: /bin/bash
      args: ["-lc", "exec npx -y @modelcontextprotocol/server-filesystem /home/alice/src"]
      idle-timeout: 12h
```

Starting a server through a login shell (`bash -lc`) gives it the `PATH` that your profile sets, which a systemd user service often lacks.
